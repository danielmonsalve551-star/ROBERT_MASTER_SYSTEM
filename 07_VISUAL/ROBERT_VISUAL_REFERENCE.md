Estados posibles:

1. Reposo  
   Robert está esperando instrucciones.

2. Escucha  
   Robert está recibiendo input.

3. Análisis  
   Robert está interpretando información.

4. Clasificación  
   Robert está decidiendo dónde va la información.

5. Borrador  
   Robert está preparando texto, documento o estructura.

   Robert necesita permiso del usuario.

7. Bloqueo de seguridad  
   Robert detectó una acción no permitida.

8. Autonomía activa  
   Robert está trabajando dentro de un alcance autorizado.

9. Sandbox  
   Robert está probando sin afectar sistemas reales.

10. Ejecución limitada  
   Robert está realizando una acción permitida dentro de límites.

## Regla principal

La vista gráfica de Obsidian debe organizarse con este criterio:

**Órbita = función arquitectónica**

**Color = capa o función visual**

La órbita indica la función del documento dentro de Robert.

El color ayuda a identificar la capa o función visual.

El color no debe usarse para representar riesgo, estado o prioridad.

---

## Núcleo — Entrada visual principal

Archivo:

- ROBERT_HOME

Función:

ROBERT_HOME funciona como entrada visual principal del sistema Robert.

Representa el punto de navegación central, pero no reemplaza la fuente de verdad.

- #robert/orbita-2

## Regla de colores

El color en Obsidian debe representar:

**Capa o función visual**

El color no debe representar:

- Estado.
- Riesgo.
- Prioridad.
- Orden alfabético.
- Estética libre.

El riesgo debe representarse en futuros componentes como:

- RiskBadge
- ApprovalGate
- DocumentStatusMap

El estado documental debe representarse en futuros componentes como:

- DocumentStatusMap
- CurrentStatePanel
- DecisionInbox

Regla:

**Un color, un significado.**

## Configuración recomendada del grafo

En Obsidian Graph View:

- Solo archivos existentes: ACTIVADO
- Huérfanos: APAGADO
- Adjuntos: APAGADO
- Etiquetas: OPCIONAL
- Flechas: OPCIONAL

Esto mantiene el grafo limpio y evita que archivos temporales o enlaces fantasmas contaminen la vista.

---

## Convención de enlaces

La estructura visual del grafo depende de wikilinks.

Cada documento maestro debe enlazar:

1. A ROBERT_HOME.
2. A sus 1 o 2 documentos vecinos más importantes.
3. A documentos técnicos relacionados cuando aplique.

No se debe enlazar todo con todo.

La regla es:

**Enlaces con intención, no enlaces por decoración.**

## Regla sobre nombres de archivos

Los wikilinks deben usar el nombre exacto del archivo en Obsidian.

Ejemplo:

Si el archivo se llama:

ROBERT_VISUAL

el enlace correcto es:

[[ROBERT_VISUAL_REFERENCE]]

No usar nombres antiguos o variantes con espacios si el archivo real ya fue renombrado con guion bajo.
